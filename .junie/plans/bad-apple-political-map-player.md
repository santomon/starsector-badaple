# Requirements

### Overview & Goals
The goal is to render the Bad Apple video on Starsector's campaign map using political spheres of influence generated by Klark Morrigan's Utilities (KMU). To provide high visual fidelity and pixel resolution on the map, the mod generates a dense, evenly distributed constellation of star systems across the sector during **New Game creation**, preserving the vanilla Core Worlds. 

All market and economy modifications are strictly separated from sector generation and handled at runtime via the dedicated `badapple_init` command.

### Scope
- **In Scope**:
  - Procedural generation of star systems during **New Game creation** (`onNewGameAfterProcGen()` in `BadAppleModPlugin`).
  - High spatial density and uniform distribution across hyperspace (Poisson Disk / blue noise distribution with calibrated minimum spacing).
  - Preservation of vanilla Core Worlds (keeping existing core systems intact and preventing overlapping generation).
  - Clean celestial generation only: instantiating star systems, primary stars (varied star types), and backgrounds **without any market, colony, or faction changes**.
  - Separation of concerns: market creation, space station spawning, exploration state, and faction alignment are managed strictly by the runtime `badapple_init` command.
  - Full compatibility with `badapple_prep`, `badapple_play`, and KMU political map rendering.
- **Out of Scope**:
  - Spawning markets or modifying faction ownership during new game sector generation.
  - Modifying base game campaign save generation files outside the mod's new game hooks.

### User Stories
- **As a video creator**, I want new game creation to generate a dense, evenly spread canvas of star systems across hyperspace so that political spheres of influence form a high-resolution display for Bad Apple.
- **As a video creator**, I want the Core Worlds preserved in their original form while new systems fill the surrounding sector canvas.
- **As a modder**, I want sector generation to create only clean celestial systems without market/economy interference, allowing market setup and faction initialization to be triggered on demand via `badapple_init`.

### Functional Requirements
1. **New Game Generation Hook**: Trigger custom procedural star system generation during `onNewGameAfterProcGen()` in `BadAppleModPlugin`.
2. **Even Spatial Distribution**: Implement Poisson Disk Sampling / Jittered Blue Noise algorithm in hyperspace coordinates $(X, Y)$ ensuring a guaranteed minimum distance $r_{min}$ between any two systems while avoiding unnatural grid lines.
3. **Core World Preservation**: Check candidate coordinates against core world boundaries and existing star systems to prevent placement overlaps.
4. **Pure Celestial Generation**:
   - Create `StarSystemAPI` instances in hyperspace.
   - Initialize primary stars with varied star types (yellow dwarf, blue giant, red dwarf, white dwarf, orange, etc.).
   - Set system backgrounds / nebulae.
   - **Zero market, colony, condition, or faction modifications during procgen**.
5. **Runtime Initialization Workflow**:
   - After starting a new game, the user executes `badapple_init` from the console to spawn stations and size-3 markets on all systems, set factions to `hegemony`, and lift fog of war.
   - `badapple_prep` maps system coordinates to Bad Apple video frames.
   - `badapple_play` streams frame updates to the campaign map.

### Non-Functional Requirements
- **Performance**: Generating 300–500 systems during new game creation should execute in < 2 seconds without hanging the loading screen.
- **Visual Quality**: System spacing should match KMU's political sphere fusion radius so adjacent same-faction systems blend smoothly while distinct factions form sharp power diagram edges.
- **Code Style**: Procedural, readable implementation with clear section comments and minimal class proliferation.

# Technical Design

### Current Implementation & Assets
- **Existing Commands**: `badapple_init`, `badapple_prep`, `badapple_play`, `badapple_poc`.
- **Mod Plugin**: `santomon.BadApple.BadAppleModPlugin`.
- **Dependencies**: Starsector API (`SectorAPI`, `StarSystemAPI`, `StarSpecAPI`), `KMU` (`MarketPoliticsRefresh`, `MapLayerRefreshBoard`), `Console Commands` (`BaseCommand`).

### Key Decisions
1. **New Game Hook vs Runtime Command**:
   - *Chosen*: Generate star systems during `onNewGameAfterProcGen()` when starting a new game.
   - *Rationale*: New game generation is the standard and robust way in Starsector to establish sector topography, ensuring star systems, jump points, and hyperspace anchors are properly registered in the engine without runtime save mutations.
2. **Strict Separation of ProcGen and Economy**:
   - *Chosen*: Sector generation ONLY creates celestial star systems and stars. Zero markets or factions are assigned during procgen.
   - *Rationale*: Keeps sector generation fast, clean, and decoupled from playback state. The user explicitly controls when to populate and align markets using `badapple_init`.
3. **Spatial Distribution Algorithm**:
   - *Chosen*: Poisson Disk Sampling (Bridson's algorithm) within a calibrated hyperspace rectangle (e.g. $40000 \times 30000$ maintaining 4:3 aspect ratio).
   - *Rationale*: Guarantees a minimum distance $r_{min}$ between adjacent systems, producing an organic yet uniformly dense canvas that avoids both clustering and void gaps.
4. **Core Worlds Exclusion Zone**:
   - *Chosen*: Exclude candidate coordinates that fall within the Core Worlds bounding radius (central $[-15000, 15000] \times [-15000, 15000]$) or within $r_{min}$ of any vanilla system.
   - *Rationale*: Preserves the integrity and visual identity of vanilla Core Worlds.

### Components & File Structure
- `src/santomon/BadApple/procgen/BadApplePoissonSampler.java`: 2D Poisson Disk sampling algorithm with minimum spacing constraint.
- `src/santomon/BadApple/procgen/BadAppleSectorGenerator.java`: Procedural star system generator that instantiates stars and registers systems in hyperspace.
- `src/santomon/BadApple/BadAppleModPlugin.java`: Overrides `onNewGameAfterProcGen()` to invoke `BadAppleSectorGenerator.generateDenseSector(sector)`.
- `src/santomon/BadApple/commands/BadAppleInitCommand.java`: Runtime command to spawn stations, create markets, and align factions across all systems.

# Testing

### Validation Approach
Verification will be done by starting a New Game in Starsector, inspecting sector generation logs, and verifying system layout on the hyperspace map.

### Key Scenarios
1. **New Game Generation**:
   - Start a new game with the mod enabled.
   - Verify that new star systems are generated across the outer sector in addition to the standard Core Worlds.
   - Verify that none of the generated systems have markets or colony structures initially.
2. **Core Worlds Integrity**:
   - Verify that Chicomoztoc, Jangala, Sindria, etc., remain in their exact vanilla positions without overlapping generated stars.
3. **Runtime Initialization (`badapple_init`)**:
   - Run `badapple_init` in the newly created game.
   - Verify that all systems (core + generated) receive space stations, size-3 markets, and `hegemony` alignment.
   - Verify KMU political map renders contiguous spheres across the dense canvas.
4. **End-to-End Playback (`badapple_prep` -> `badapple_play`)**:
   - Run `badapple_prep` and then `badapple_play 0.5`.
   - Verify high-resolution Bad Apple playback on the political map.

### ✓ Step 2: Implement preprocessing command with hyperspace mapping and frame sampling
The preprocessing command inspects all star systems, normalizes coordinates to frame resolution, samples JPEG frames, and produces a sequence of market changes.

- Implement `BadApplePreprocessCommand` extending `BaseCommand` with procedural top-to-bottom logic and commented blocks.
- Block 1 (System discovery): Traverse `Global.getSector().getStarSystems()`, filter valid systems with markets, and calculate the hyperspace bounding box `(minX, maxX, minY, maxY)`.
- Block 2 (Coordinate normalization): Map each star system's `(x, y)` location to image pixel space `(0..width-1, 0..height-1)` matching the 480x360 frame dimensions.
- Block 3 (Frame processing & delta extraction): Load `output_XXXX.jpg` from `graphics/badapple/frames/` sequentially using Java ImageIO, sample pixel brightness at each system coordinate, determine target faction (`sindrian_diktat` vs `hegemony`), and record changed markets into a `List<BadAppleFrameData>`.
- Block 4 (Session caching): Cache the generated frame change sequence in memory for consumption by the player command.

### ✓ Step 3: Implement playback execution command and KMU update script
The playback command consumes preprocessed frame changes at a configurable pace, updates market factions, and triggers KMU political map redraws.

- Support command arguments: delay between frame steps (in seconds or game ticks), start frame index, pause/resume, and reset.
- Block 1 (State application): On each frame tick, retrieve the current frame's market changes and apply `market.setFactionId(newFactionId)` to the target colonies.
- Block 2 (KMU political map refresh): Call `MarketPoliticsRefresh.reportMarketChange(...)` and signal KMU's `MapLayerRefreshBoard` (`MapLayerCommonRefreshSignal.GEOMETRY`) to redraw political spheres.
- Block 3 (Diagnostics & feedback): Log playback progress to console / screen overlay to facilitate footage capture in external screen recording software.
